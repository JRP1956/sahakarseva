# Backend Implementation Plan (Plan 1 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** FastAPI + PostGIS backend exposing auth, services, workers, bookings (with geo-matching, pricing, lifecycle), payments (Razorpay test), ratings, invoices, admin stats and XGBoost forecast — seeded with Mumbai demo data.

**Architecture:** Single FastAPI app, SQLAlchemy 2 models, Alembic migrations, business logic in `app/services/*.py` pure functions that take a Session. PostGIS via GeoAlchemy2. ML is a plain module under `backend/ml/` invoked by an admin endpoint.

**Tech Stack:** Python 3.12 (uv), FastAPI, SQLAlchemy 2, GeoAlchemy2, Alembic, psycopg, pydantic v2, python-jose, passlib[bcrypt], razorpay, pandas, xgboost, pytest, httpx. PostgreSQL 16 + PostGIS via Docker.

**Spec:** `docs/superpowers/specs/2026-09-14-coop-gig-platform-design.md`

## Global Constraints

- API prefix `/api/v1`; OpenAPI at `/docs`.
- Roles: `customer`, `worker`, `admin`. JWT access 15 min, refresh 30 d.
- Pricing: `customer_price = base_price * (1.5 if emergency else 1)`; worker 80% / coop 20% default from `services` row.
- Match: 10 km radius, weights 35/25/15/10/10/5 exactly as spec.
- Booking status enum: `requested, assigned, accepted, in_progress, completed, paid, rated, cancelled`.
- Files stored under `backend/uploads/`.
- All tests run against a PostGIS DB at `TEST_DATABASE_URL` (docker compose service `db`, database `gig_test`).

class Worker(Base):

### Task 5: Matching service

**Files:** `app/services/matching.py`, `tests/test_matching.py`

**Produces:**
```python
@dataclass
class Candidate: worker: Worker; distance_km: float; score: float; breakdown: dict[str, float]
def score_worker(*, skill_match: float, distance_km: float, available_now: bool, rating_avg: float, experience_years: int, jobs_this_week: int) -> tuple[float, dict]
def find_candidates(db, service_id: int, lat: float, lng: float, scheduled_at: datetime, limit=5) -> list[Candidate]
```
- [ ] Tests (pure `score_worker` first): all-max inputs → 100; distance 10 km → distance component 0; worker with 3 jobs beats identical worker with 12 jobs; out-of-radius excluded (DB test with two seeded workers at 2 km and 15 km).
- [ ] Query:
```python
dist = func.ST_Distance(Worker.location, func.ST_MakePoint(lng, lat).cast(Geography))
q = (select(Worker, dist.label("d"))
     .join(WorkerSkill).join(Skill).where(Skill.service_id == service_id,
           Worker.is_available.is_(True),
           func.ST_DWithin(Worker.location, point, 10_000),
           ~exists().where(Booking.worker_id == Worker.id,
                           Booking.status.in_([accepted, in_progress]),
                           func.abs(func.extract("epoch", Booking.scheduled_at - scheduled_at)) < 7200))
     .distinct())
```
Skill match = 1.0 (all query hits have the skill) + 0.1 per extra skill in same category, cap 1.0. Sort by score desc, return top `limit`. Commit.
